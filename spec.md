multi-graph thingie

what i want is a nice little graph tool, with the functionality of https://insightmaker.com/docs/manual (SD), some inspiration from https://machinations.io/ for the UI/viz parts, but should probably use node graph widgets/functions more like https://kageproduction.com/persistentnodes or other FL Studio patcher/plugin thingies. n8n/nodered are another inspirational sample.

instead of line-chart outputs like insight-maker, i want to see animations like machinations/fl studio, and the conditionals, variables, etc should determine which links show as active, and colors should be clear visual indicators for nodes or edges as to if they're over/under their baseline (eg: blue=low, red=high, gray/default=avg). the goal is to be able to hook up many complex nodes, set up variables/dials etc, run it, and see which paths/nodes light up and how strongly, and watch it change over time (delay, feedback loops, balancing loops, etc).

there should also be well-placed pop-up imputs or a more full right-panel with all the settings for a given widget. and i should be able to pause a simulation, shift one or more node/edge values or functions in whatever ways, then play/resume, and see the system continue from those settings. aka i want to create some sort of perturbation, and see if it re-balances, sticks, or spirals in some eventually self-sustaining feedback loop, oscillates, or whatever else.

ideally there's also a way to zoom in and out of a complex node, like zooming into an IC on a circuitboard, for layers of abstraction, and each "IC" type node should be able to funnel inputs/outputs from its full sub-network or be more independent or take some function that samples its inner-nodes but with less detail/fidelity, however is useful in a situaiton. nodes on different layers should be able to connect to other nodes on their layer or other layers, ideally. different tabs/pages for graphs that can be called from one another (ala n8n etc) would be good to have also.

this can be web or desktop based, whatever works best. it needs a simplistic format in json or yaml to import/save graphs to and from. you can use any language or framework that's well-suited so long as it's free/open licensed. if you need a tool, check or ask, many are already available somewhere on the system, including several databases and related services. init and use a git repo, i'll set up a remote if/when we get to where it's useful. keep the goal in mind and work towards a MVP, then fill in further details as warranted. work wide, to set the foundation, then deep, but there's no need to stop between unless you have questions or run into blockers.
